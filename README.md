# Сервисный центр

Учебное консольное приложение на Java для учёта клиентов и заявок на ремонт.

- `task1` — первая аттестация: хранение в памяти и консольный интерфейс.
- `task2` — вторая аттестация: PostgreSQL через JDBC, запуск в Docker.

## Клонирование

```bash
git clone --branch task2 https://github.com/exzoe/service-center.git
cd service-center
```

## Запуск в Docker

С запущенным Docker Desktop в папке проекта выполните:

```bash
docker compose run --build --rm app
```

Команда собирает приложение, запускает тесты, поднимает PostgreSQL и открывает меню.
Таблицы создаются при первом запуске. Данные сохраняются в томе между запусками.
Для выхода введите `exit`, для остановки базы — `docker compose down`.

## Запуск без Docker

Нужны JDK 21 и PostgreSQL. Gradle загружается через Wrapper.

1. Создайте базу `service_center` и выполните в ней `src/main/resources/schema.sql`.
2. Укажите свои параметры в `src/main/resources/database.properties`:

```properties
db.url=jdbc:postgresql://localhost:5432/service_center
db.user=home
db.password=
```

3. Соберите и запустите приложение:

```bash
./gradlew clean build
./gradlew --console=plain run
```

На Windows используйте `.\gradlew.bat` вместо `./gradlew`.
Переменные окружения `DB_URL`, `DB_USER`, `DB_PASSWORD` имеют приоритет над файлом настроек.

## Возможности

| Команда | Действие |
| --- | --- |
| `client-add` | Добавить клиента: имя и телефон |
| `client-list` | Показать клиентов и их ID |
| `order-create` | Создать заявку для существующего клиента |
| `order-list` | Показать все заявки |
| `order-status` | Изменить статус заявки |
| `order-update` | Изменить устройство и описание неисправности |
| `order-delete` | Удалить новую заявку |
| `order-find` | Найти заявки по статусу |
| `exit` | Выйти |

Для создания заявки нужен ID клиента. ID назначает PostgreSQL автоматически.
При выборе статуса вводится его номер из списка.

## Правила работы с заявками

Новая заявка получает статус `NEW`. Разрешённые переходы:

| Текущий статус | Допустимый следующий статус |
| --- | --- |
| `NEW` — принята | `DIAGNOSTICS`, `CANCELLED` |
| `DIAGNOSTICS` — диагностика | `IN_REPAIR`, `CANCELLED` |
| `IN_REPAIR` — ремонт | `READY` |
| `READY` — готова к выдаче | `CLOSED` |
| `CLOSED` — выдана | Переходов нет |
| `CANCELLED` — отменена | Переходов нет |

Повторное назначение того же статуса запрещено. Редактировать и удалять заявку
можно только в статусе `NEW`. Имя, телефон, устройство и описание не должны быть
пустыми. Формат телефона отдельно не проверяется.

## Пример работы

1. Добавьте клиента командой `client-add` и запомните его ID.
2. Создайте заявку через `order-create`, проверьте её через `order-list`.
3. Проведите заявку по цепочке `NEW → DIAGNOSTICS → IN_REPAIR → READY → CLOSED`
   командой `order-status`.
4. Перезапустите приложение и проверьте, что данные сохранились.

## Тесты

```bash
./gradlew test
```

JUnit Jupiter: создание клиентов и заявок, смена статусов, редактирование,
удаление и проверки неверных данных. Тесты используют репозитории в памяти,
PostgreSQL не требуется. Работа JDBC проверена вручную.

Отчёт: `build/reports/tests/test/index.html`.

## Структура проекта

- `domain` — клиент, заявка и статусы.
- `validation`, `exception` — проверка данных и ошибки приложения.
- `repository` — интерфейсы; `jdbc` — PostgreSQL, `memory` — хранение для тестов.
- `id` — генератор ID для репозиториев в памяти.
- `config` — чтение настроек (`ConfigReader`), их хранение (`DatabaseConfig`)
  и открытие соединений (`ConnectionProvider`).
- `service` — бизнес-логика и правила работы с заявками.
- `ui`, `ui.command` — консольное меню и команды.
- `factory` — сборка приложения; `Main` — точка входа.
- `src/main/resources` — схема БД и параметры подключения.
- `src/test/java` — автоматические тесты.

Веб-интерфейс на сервлетах планируется для третьей аттестации.
