# Сервисный центр

Учебное консольное приложение на Java для учёта клиентов и заявок на ремонт.
Первая аттестация: предметная модель, хранение в памяти и консольный интерфейс.
Код первой аттестации находится в ветке `task1`.

## Требования

- JDK 21. Проверить установленную версию можно командой `java -version`.
- Git для клонирования репозитория.
- Доступ к интернету при первой сборке для загрузки Gradle и зависимостей тестов.

Gradle отдельно устанавливать не нужно: в репозитории есть Gradle Wrapper,
который загружает версию 9.6.0. IDEA, база данных и Docker для запуска не нужны.
Если установлено несколько JDK, укажите JDK 21 в `JAVA_HOME` и убедитесь, что
`java` доступна в `PATH`.

## Клонирование и сборка

Клонируйте ветку первой аттестации:

```bash
git clone --branch task1 https://github.com/exzoe/service-center.git
cd service-center
```

На macOS и Linux выполните:

```bash
./gradlew clean build
```

На Windows в PowerShell:

```powershell
.\gradlew.bat clean build
```

Команда компилирует проект, запускает тесты и создаёт артефакты сборки в `build/`.
Ожидаемый результат успешной сборки — `BUILD SUCCESSFUL`.
При первом запуске загрузка Gradle и зависимостей может занять время.

## Запуск

На macOS и Linux:

```bash
./gradlew --console=plain run
```

На Windows в PowerShell:

```powershell
.\gradlew.bat --console=plain run
```

Выберите пункт меню по номеру. Для завершения работы введите `0`.

## Windows: кодировка и известное ограничение

Сборка, тесты и запуск свежего клона проверены на macOS с JDK 21.
При проверке на Windows 10 с JDK 17 и классической командной строкой наблюдались
ошибки кодировки при компиляции, искажённые русские надписи и потеря кириллицы
при вводе имени клиента. Корректная работа русского ввода на Windows после
изменения настроек пока не подтверждена.

Для повторной проверки на Windows:

1. Установите JDK 21 и откройте новый терминал. Проверьте `java -version` и
   `.\gradlew.bat --version`: Java, Launcher JVM и Daemon JVM должны использовать
   JDK 21. При необходимости исправьте `JAVA_HOME` и `PATH`.
2. Используйте актуальный Windows Terminal. В том же окне переключите кодовую
   страницу на UTF-8 и пересоберите проект:

```powershell
chcp 65001
.\gradlew.bat --stop
.\gradlew.bat clean build
.\gradlew.bat --console=plain run
```

В `build.gradle` кодировка компиляции Java-файлов явно задана как UTF-8.
Эта настройка отвечает за чтение исходников, но не настраивает консольный ввод
и вывод. После исправления кодировки нужна чистая пересборка (`clean build`),
чтобы не использовать старые классы.

Проверьте не только читаемость меню, но и сохранность введённых данных:
добавьте клиента с русским именем и выведите список клиентов. Если вместо букв
появляются `?`, пропуски или другие символы, проблема консольной кодировки
остаётся. Само сообщение `BUILD SUCCESSFUL` не подтверждает корректность
интерактивного ввода. Указанные шаги не гарантируют устранения проблемы во всех
версиях консоли Windows.

## Возможности

| Пункт | Действие |
| --- | --- |
| 1 | Добавить клиента: имя и телефон |
| 2 | Показать клиентов и их ID |
| 3 | Создать заявку для существующего клиента |
| 4 | Показать все заявки |
| 5 | Изменить статус заявки |
| 6 | Изменить устройство и описание неисправности |
| 7 | Удалить новую заявку |
| 8 | Найти заявки по статусу |
| 0 | Выйти |

При выборе статуса приложение показывает нумерованный список: вводится номер,
а не название константы. Идентификаторы клиентов и заявок назначаются сервисами
автоматически. Для создания заявки нужно указать ID уже добавленного клиента.
Ошибки ввода и запрещённые действия отображаются сообщением в консоли.

## Правила работы с заявками

Новая заявка получает статус `NEW`. Разрешённые переходы:

| Текущий статус | Допустимый следующий статус |
| --- | --- |
| `NEW` — принята | `DIAGNOSTICS`, `CANCELLED` |
| `DIAGNOSTICS` — диагностика | `IN_REPAIR`, `CANCELLED` |
| `IN_REPAIR` — ремонт | `READY` |
| `READY` — готова к выдаче | `CLOSED` |
| `CLOSED` — выдана | Переходов нет |
| `CANCELLED` — отменена | Переходов нет |

Повторное назначение того же статуса также запрещено.
Редактировать устройство и описание или удалять заявку можно только в статусе
`NEW`. Имя клиента, телефон, устройство и описание неисправности не должны быть
пустыми или состоять только из пробелов. Формат телефонного номера отдельно
не проверяется.

## Пример работы

1. Добавьте клиента через пункт `1` и запомните выведенный ID.
2. Через пункт `3` создайте заявку для этого клиента.
3. Откройте пункт `4`, чтобы увидеть заявку и её ID.
4. Пока заявка новая, при необходимости исправьте данные через пункт `6`.
5. Через пункт `5` проведите заявку по цепочке
   `NEW → DIAGNOSTICS → IN_REPAIR → READY → CLOSED`.
6. Используйте пункт `8` для поиска заявок с нужным статусом.

## Тесты

На macOS и Linux:

```bash
./gradlew test
```

На Windows в PowerShell:

```powershell
.\gradlew.bat test
```

В проекте 9 тестов на JUnit Jupiter:

- `RepairOrderTest`: разрешённый и запрещённый переход статуса, редактирование
  новой заявки, сохранение данных при ошибке и запрет редактирования после
  начала диагностики.
- `RepairOrderServiceTest`: отказ в создании заявки без клиента, создание и
  сохранение заявки, удаление новой заявки и запрет удаления после начала
  диагностики.

HTML-отчёт после выполнения тестов: `build/reports/tests/test/index.html`.

## Структура проекта

- `domain` — клиент, заявка и перечисление статусов; правила изменения заявки.
- `repository` — интерфейсы доступа к данным.
- `repository.memory` — хранение клиентов и заявок в коллекциях `HashMap`.
- `service` — создание, поиск и обработка данных с использованием репозиториев.
- `ui` — консольное меню, чтение ввода и вывод результатов.
- `Main` — создание и связывание репозиториев, сервисов и консольного интерфейса.
- `src/test/java` — автоматические тесты.

## Хранение и дальнейшее развитие

Данные хранятся только в памяти текущего процесса. После выхода все клиенты и
заявки исчезают, а счётчики ID начинаются заново. В `Main` создаётся по одному
экземпляру каждого сервиса с изначально пустыми репозиториями.

На следующих аттестациях планируется добавить хранение в базе данных и
веб-интерфейс на сервлетах. Сейчас эти возможности не реализованы.
